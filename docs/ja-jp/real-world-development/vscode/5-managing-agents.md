GitHub Copilot を agent mode で使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムに確認できます。差分をインラインで確認し、個々の変更を受け入れるか取り消すかを選び、追加のプロンプトで作業を調整できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- 実行中のセッションを案内し、ハイ コントラスト モードにライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードも追加したいという要望がありました。新しい会話を始めるのではなく、既存のセッションを案内して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順（調査するファイル、実行するコマンド、提案する編集）が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. ファイル編集が提案されたら、差分を確認します。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業を依頼します。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの呼び出し（ターミナル コマンドの実行など）で許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可する前にコマンドを確認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。変更を要約する最終メッセージが表示されます。

## ライト モードを追加するようエージェントを案内する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを使うため、エージェントは以前に変更したコンポーネント、スタイル、local storage のパターンなどのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調べ、ライト モードの追加を提案します。
3. 新しい編集を確認し、ハイ コントラスト モードと同様に各差分で **Keep** または **Undo** を選択します。
4. エージェントの方向が希望と異なる場合（たとえば切り替え UI を意図しない形でリファクタリングする場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、補足プロンプトを送ります。

> [!TIP]
> 実行中のセッションを案内すると、最初からやり直すより速く調整できます。追加のプロンプトで変更（「CSS を簡潔にし、selector の重複ではなく CSS 変数を使う」）、方向の修正（「3 つ目の toggle は追加せず、既存の設定パネルにライト モードを統合する」）、範囲の拡張（「両方の toggle にキーボード ショートカットも追加する」）を依頼できます。

## 作業内容をレビューする

commit する前に、エージェントが変更したファイル全体を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが示したアクセシビリティのパターン（ARIA 属性、キーボード操作、セマンティック HTML、local storage による保存）が使われていることを確認します。
4. 問題がなければ、Source Control パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で進行中のセッションを監視して調整しました。ファイル編集ごとにレビューし、変更を受け入れるか取り消し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を受け入れるか取り消す
- 実行中のセッションに追加プロンプトを送り、方向を調整する
