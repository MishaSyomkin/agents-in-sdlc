最初にプロジェクトに小さな機能を追加しました。大きな変更には、より確実なプロセスが必要です。GitHub Copilot app は組織の既存の開発フローに沿って動作し、必要なものを適切な方法で構築できるようにします。このレッスンから数回にわたり、issue から新機能を始め、コードと機能を検証し、プロジェクトにマージするまでの一般的なエージェント主導の開発を進めます。

> [!NOTE]
> 機能開発を続ける間は同じセッションを使います。通常はファイルの種類ごとに異なるセッションや PR を使いますが、ここでは中心的な概念に集中するため簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から新しいエージェント セッションを開始します。
- **Plan** モードで要件を決めます。
- **Autopilot** モードで機能を実装します。
- コードをレビューします。
- ブラウザー キャンバスで機能を手動検証します。

機能開発を続けながら、リポジトリの命令を更新し、既存の quality-checks スキルを調整し、MCP による検証を追加し、QA エージェントを作成して、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がゲームをカテゴリやパブリッシャーで絞り込めるようにします。バックログの issue には機能の概要がありますが、カテゴリの組み合わせ方など、実装前に合意したい細部もあります。Plan モードで方針を決めた後、範囲を限定して Autopilot に実装を任せます。

## 背景

AI コーディング エージェントを開発フローに加えても、基本は変わりません。むしろ、基本を守ることが一層重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業の詳細を記した issue を開きます。
2. 実装する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 詳細な手順はチームや組織によって異なりますが、ほとんどの開発フローはこの流れを基本にしています。

標準的な進め方に沿うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビューを受けるようにできます。

## セッション モード

**セッション モード**は、エージェントにどの程度の自律性を与えるかを制御します。プロンプト欄の下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: 開発者とエージェントが協力します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントがまず計画を作成します。実行前に計画をレビューして承認します。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、入力を待たずに反復します。

Plan モードで開始し、計画をレビューしてから、Autopilot で実装します。

## issue からセッションを開始する

開始する前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリ フォルダーを選択し、リポジトリの上部ナビゲーションで **Issues** を選択します。既存の **Allow users to filter games by category and publisher** issue を開きます。テンプレートに用意された issue のため、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` を基にした **new working tree** を選びます。

   ![GitHub Copilot app の issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. issue がセッションに添付されていることを確認し、モード選択で **Plan** を選びます。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行するよう依頼します。通常のターミナルでは使えるのにセッション内で使えない場合は、アプリの PATH またはバージョン管理ツールの設定を確認し、アプリを完全に終了してから再起動します。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで npm を再インストールしないでください。

## フィルタリング機能を計画する

計画を立てることで、Copilot がコードを書く前にアプローチを確認できます。issue から開始したので、Copilot はすでに機能のリクエストをコンテキストとして持っています。次を送信します。

```plaintext
この機能を実装してください。
```

Copilot の質問に回答し、計画を issue の受け入れ条件と照らし合わせます。カテゴリとパブリッシャーの絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが含まれていることを確認します。複数カテゴリの組み合わせや、ゲームが見つからない場合の動作など、不明確な点を話し合います。

計画には、既存のプロジェクト ツールを使った lint、単体テスト、エンドツーエンド (E2E) テスト、型チェックを含めます。フィルタリングの実装とテストに範囲を絞り、品質ワークフローが完了するまで PR は作成しません。計画は承認前に修正を依頼します。後で検証できるよう、issue の URL と合意した補足事項を控えておきます。

## Autopilot を明示的に承認する

計画に問題がなければ、**Approve and implement this plan**、または使用中のバージョンで同等の選択肢を選びます。承認しただけでモードが切り替わると思い込まず、モード表示が **Autopilot** になっていることを確認します。

Copilot は実装を始め、計画に沿ってコードを生成してテストを実行しながら反復します。

> [!NOTE]
> 承認すると実装がすぐに始まる場合があるため、先に計画をレビューしてください。依存関係の不足やポート競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決します。自分が起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同じようにマージ前にレビューします。コードを確認し、サイトを実行して動作も確かめます。

1. **Changes** を開き、フィルタリングの実装とテストを確認します。
2. 複数カテゴリとパブリッシャーの組み合わせを含め、結果を issue と承認済みの補足事項に照らし合わせます。変更が既存のリポジトリ命令に従っていることを確認します。
3. lint、単体テスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、影響を受けるチェックを再実行します。Playwright の E2E 設定はプレビューをビルドして配信し、ローカル サーバーを再利用する場合があります。以前のレッスンではなく、この worktree のサーバーがテスト対象であることを確認します。

## 新機能を試す

コードに問題がないように見えても、実際に動くか確認します。Copilot にアプリを起動させ、ブラウザー キャンバスでサイトを開きます。

1. 次のプロンプトを送信し、アプリを起動してブラウザー キャンバスで開くよう依頼します。

   ```plaintext
   アプリを起動し、ブラウザー キャンバスで開いてください。
   ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザー ウィンドウが開きます。
3. カテゴリを選択し、結果がカテゴリに一致することを確認します。フィルターを解除してからパブリッシャーを選択し、結果を確認します。
4. カテゴリとパブリッシャーを組み合わせ、issue と承認済みの計画に結果が一致することを確認します。複数カテゴリに対応する場合は、合意した組み合わせ方も検証します。
5. 結果が 0 件になる組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットして、一覧全体が戻ることも確認します。
6. 確認が終わったら、次のプロンプトでこのセッションが起動した開発サーバーを停止します。

   ```plaintext
   開発サーバーを停止し、ブラウザー キャンバスを閉じてください。
   ```

## 次のレッスンのためにセッションを保持する

フィルタリングの PR はまだ作成またはマージしません。レッスン 4 から 8 まで同じセッション、worktree、ブランチを使います。次はカスタム命令をフィルタリングのコードに適用し、その後スキルと QA の改善を追加してから、レッスン 8 で変更をまとめて PR を作成、マージします。開発サーバーを停止した後、セッションはそのままにします。次のレッスンで同じセッションに戻ります。

- **Autopilot** モードで機能を実装しました。
