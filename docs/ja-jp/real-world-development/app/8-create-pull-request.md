フィルタリングの実装、命令とスキルの更新、品質保証 (QA) プロファイル、テストが 1 つのブランチに保存されています。これらをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスを任せます。

> [!NOTE]
> 通常は機能、命令の更新、スキル、QA エージェントを複数の PR に分けます。ワークショップを簡潔に進めるため、フィルタリングと品質ワークフロー全体を 1 つのセッションとブランチで進め、この PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge と、マージのライフサイクルを自動化する仕組みを学びます。
- 機能の PR 全体と検証結果を確認します。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルタリングのワークフローでは、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys では、マージの許可を開発者が管理しながら、PR の残りの作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするまでに必要な残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエスト (PR) を読み取り、失敗した継続的インテグレーション (CI) チェックの修正、レビュー コメントへの対応、必要に応じた rebase など、マージを妨げている問題に取り組みます。GitHub が許可するとマージします。バックグラウンドで実行され、アプリの再起動後も続き、PR がマージされると自動的に停止します。

ここまでは **Merge pull request** を自分で選択していました。Agent Merge に任せることもできますが、コードの編集やマージには明示的な許可が必要です。マージを許可する前に、許可される操作と作業内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが終わったら、Agent Merge に PR プロセスを管理させます。

1. agent picker で **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択して処理を開始します。ドロップダウンの選択だけでは始まりません。

Agent Merge は次の作業を行います。

- タイトルと説明を含むプルリクエストを作成します。
- issue からセッションを開始した場合は、PR の説明に関連する issue を記載します。
- 必要に応じて rebase を行い、ターゲット ブランチとのマージ競合に対処します。
- CI を監視し、すべてのチェックが成功するようにします。
- 他の開発者や Copilot code review からのフィードバックを確認し、コメントを解決する変更を加えます。
- 必要に応じて、すべての条件が満たされた後に PR を自動的にマージします。

すべての条件が満たされたら、Agent Merge に PR をマージさせます。

5. マージを許可する前に、PR の差分と検証結果をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** にチェックが付いていることを確認します。
8. 次のようにエージェントに明示的に依頼します。

   ```plaintext
   必須のチェックと承認がすべて成功したら PR をマージしてください。リポジトリの保護設定は回避しないでください。
   ```

9. 進捗を確認し、報告されたブロッカーに対処します。続行する前に、PR の状態が **Merged** になっていることを確認します。マージ権限の有効化やエージェントの実行中表示だけでは、マージ完了の確認になりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護設定や権限不足を回避しません。続行する前にブロッカーを解消してください。
